# gopf

gopf 是一个简单的 TCP 端口转发器。一个进程可以监听多个地址，每个监听地址固定转发到一个目标；它不解析 HTTP，也不会在目标连接失败时自动重试。

## 构建和运行

需要 Go 1.25.6 或更新版本，适用于 macOS 和 Linux。

```sh
go build -o gopf .
./gopf settings.conf
```

监听地址和目标都写在配置中。例如，两个端口分别转发到两个目标：

```json
{
  "forwards": [
    { "listen": "127.0.0.1:1248", "target": "127.0.0.1:8080" },
    { "listen": "127.0.0.1:1249", "target": "127.0.0.1:8081" }
  ]
}
```

启动前，确保目标已经监听。每个监听地址只能出现一次；目标必须包含主机和有效端口。

## 配置 reload

修改配置后向进程发送 `SIGHUP`，可以添加、删除监听端口或修改目标：

- 已有连接继续使用原来的目标，新连接使用新目标。
- 删除规则只停止接入新连接，已有连接继续转发。
- 配置有误或新增端口绑定失败时，保留全部旧规则。
- 显式配置 `{"forwards":[]}` 会停止所有监听；省略 `forwards` 字段会报错。

`SIGUSR1` 会记录 goroutine 数量和堆栈；`SIGINT` 或 `SIGTERM` 退出进程。

### 同一监听地址，修改目标

将 `listen1 → target1` 改为 `listen1 → target2`，发送 `SIGHUP` 且 reload 成功后：

- `listen1` 继续监听，已有转发连接继续使用 `target1`，直到连接断开。
- 新接入的 TCP 连接转发到 `target2`。
- HTTP Keep-Alive 等长连接上的后续请求仍走 `target1`，重新建连后才走 `target2`。

如果 `target2` 连不上，新连接会关闭；已有的 `target1` 转发连接不受影响。

### 保持目标，更换监听地址

将 `listen1 → target1` 改为 `listen2 → target1` 后发送 `SIGHUP`。程序先绑定 `listen2`，成功后再停止 `listen1` 的监听：

- 新连接通过 `listen2` 转发到 `target1`，`listen1` 不再接收新连接。
- 已通过 `listen1` 建立的转发连接继续使用 `target1`，直到连接断开。

如果 `listen2` 被占用或与现有监听地址冲突，reload 失败，`listen1` 保持原样。

## 基准测试

基准测试只依赖 Go，在仓库根目录执行：

```sh
go run ./bench
```

运行器自动构建 gopf，启动返回固定 396 字节内容的本地 HTTP 后端，并生成临时代理配置。随后用内置 Go 压测器分别直连后端、经过代理，各跑一次。结束、失败或按 Ctrl+C 时自动清理自己启动的进程和临时文件。

默认每条路径发送 10,000 个请求，并发 100，每个请求新建连接。只有三个参数：

| 参数 | 含义 | 默认值 |
| --- | --- | --- |
| `-n` | 每条路径的请求总数 | `10000` |
| `-c` | 并发数 | `100` |
| `-k` | 使用 HTTP Keep-Alive | `false` |

```sh
go run ./bench -n 20000 -c 50
go run ./bench -k
go run ./bench -h
```

每条路径输出成功/失败请求数、并发数、总耗时、QPS，以及成功请求的平均、P50、P99 延迟。QPS = 成功请求数 / 总耗时；每个请求最多等待 5 秒，非 2xx 响应或建连、读写失败计入失败。出现请求失败时仍显示两条路径的结果，最后以非零状态退出。

想再观察一次就重新运行；需要保存输出时可重定向到文件：

```sh
go run ./bench > bench.txt 2>&1
```

后端固定监听 `127.0.0.1:18080`，代理固定监听 `127.0.0.1:1248`；端口已被占用时直接报错。运行器继承 `GOMAXPROCS`，需要固定 Go 并行度时可执行 `GOMAXPROCS=1 go run ./bench`。
